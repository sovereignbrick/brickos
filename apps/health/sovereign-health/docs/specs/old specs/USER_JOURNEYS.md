# User Journeys
**6 Key Flows — How Users Actually Use the App**

---

## 🎯 Purpose

Instead of designing screens in isolation, we map **how users flow through the app** to accomplish real goals. This reveals:
- Missing screens or steps
- Awkward transitions
- Where users might get stuck
- What information they need at each step

---

## 🔄 JOURNEY 1: "Add Today's Measurements"

**Goal:** I just woke up and measured my blood glucose + weight. I want to log it.

**Duration:** 2–3 minutes  
**Frequency:** 2–3x per week  
**Entry Point:** Dashboard or notification

```
START: Dashboard (user sees recent measurements)
   ↓
User taps: [+ Add Measurement]
   ↓
FORM: New Measurement (modal or full page)
   • Date: 2026-03-01 (auto-filled, today)
   • Time: 06:00 (auto-filled, or user changes)
   • Device: [Fora 6 ▼] (auto-filled, last used)
   ↓
User enters metrics:
   • Blood Glucose: 5.8 mmol/L  → Status: 🟢 (live)
   • Weight: 73.0 kg            → Status: 🟢 (live)
   ↓
User adds journal (optional):
   "Carnivore, 9h sleep, good energy"
   ↓
User tags (optional):
   [#carnivore] [#fasting]
   ↓
User clicks: [Save]
   ↓
SUCCESS: Toast "✓ Measurement saved"
   ↓
NEXT: Return to Dashboard, new measurement appears at top
       Zone scores may update (e.g., Energy zone now 7/7 instead of 6/7)
```

**Key Moments:**
- ✓ Form should be quick (5 fields max for basic use)
- ✓ Live status feedback (user sees 🟢 as they type)
- ✓ Auto-filled date/time/device (reduce typing)
- ✓ Instant confirmation (see data saved immediately)

**Potential Issues:**
- ❌ Date/time picker too slow → users abandon
- ❌ Required fields aren't obvious → form submit fails
- ❌ No offline support → can't save if network drops
- ❌ Form lost if app closes → data entry wasted

## 🎯 JOURNEY 2: "I Saw Something Odd, What Does It Mean?"

**Goal:** My glucose was 6.1 yesterday (unusual). Why? What should I do?

**Duration:** 5–10 minutes  
**Frequency:** Weekly (investigating anomalies)  
**Entry Point:** Dashboard notification or manual search

```
START: Dashboard
   User sees: [🟡 6.1 mmol/L] (yellow badge, stands out)
   ↓
User taps on the measurement
   ↓
DETAIL VIEW: Single Measurement
   • Date: 2026-02-28 @ 06:00
   • Glucose: 6.1 mmol/L 🟡
   • Context: "Honey in coffee, 8h sleep, some stress"
   • Device: Fora 6
   ↓
User taps: [Why is this high?]
   ↓
KNOWLEDGE BASE: "Blood Glucose High" article
   • "Possible causes: diet, fasting duration, stress, sleep"
   • "Check your journal: you had honey (fructose spikes glucose)"
   • "Action: Reduce honey or increase fasting window"
   ↓
User taps: [Learn about Honey]
   ↓
KB ARTICLE: "Honey Effect on Glucose"
   • "55% fructose, causes 0.5–1.0 mmol/L spike"
   • "Timeline: Effect visible within 2 hours"
   • "Your data: +0.9 mmol/L rise on honey days"
   ↓
User taps: [View Trend]
   ↓
TRENDS SCREEN: Glucose last 30 days
   • Chart shows: 5.2, 5.1, 5.8 🟡, 5.3, 5.2, 5.9 🟡
   • Pattern visible: Spikes on days 3 and 6
   • User notes: "Days 3 & 6 were honey days"
   ↓
User sees correlation explained
   ↓
DECISION: "I'll try removing honey for 2 weeks"
   ↓
User creates reminder or note in app
   ↓
SUCCESS: User has understanding + action plan
```

**Key Moments:**
- ✓ Quick access to context (journal notes visible)
- ✓ KB article directly linked from measurement
- ✓ Trend view shows pattern with annotations
- ✓ User connects dots themselves (empowered, not told)

**Potential Issues:**
- ❌ KB articles too vague → user doesn't understand
- ❌ Can't see trend from detail view → have to navigate away
- ❌ No way to mark "I'm testing this change" → hard to track experiment
- ❌ Can't export data to show doctor → feels isolated

## 👨‍⚕️ JOURNEY 3: "I Want to Share This with My Doctor"

**Goal:** My doctor asked for my glucose trends. I want to send them a summary.

**Duration:** 2–5 minutes  
**Frequency:** Quarterly (before doctor visit)  
**Entry Point:** Settings or Trends screen

```
START: Dashboard or Trends screen
   ↓
User finds: [Share] or [Export] button
   ↓
SHARE OPTIONS:
   • Export to PDF
   • Export to CSV
   • Share link (encrypted, time-limited)
   • Print-friendly view
   ↓
User selects: [Export to PDF]
   ↓
OPTIONS:
   • Date range: [Last 30 days ▼] or [Custom ▼]
   • Include: [✓] Glucose [✓] Insulin [✓] Context
   • Format: [Professional report] or [Raw data]
   ↓
User clicks: [Generate PDF]
   ↓
PDF created:
   • Title: "Health Measurement Report (Jan 1 – Mar 1, 2026)"
   • Summary: "30 measurements, 95% in range, trend stable"
   • Chart: 30-day glucose trend with annotations
   • Table: All measurements + context
   • Footer: "Generated by Sovereign Health App"
   ↓
User taps: [Download] or [Share via Email]
   ↓
SUCCESS: PDF downloaded or shared with doctor
```

**Key Moments:**
- ✓ Easy export in professional format
- ✓ Options to customize what's included
- ✓ Summary statistics (help doctor quickly understand)
- ✓ Clear attribution (not pretending to be medical test)

**Potential Issues:**
- ❌ Export hidden in settings → user can't find it
- ❌ PDF is raw data dump → doctor can't read it
- ❌ No summary statistics → doctor has to calculate
- ❌ Export takes doctor's app name off → looks unprofessional

## 📈 JOURNEY 4: "I'm Optimizing. What Should I Try Next?"

**Goal:** My glucose is good, but insulin is still 3.2. What's the next lever?

**Duration:** 10–15 minutes  
**Frequency:** Monthly (optimization cycle)  
**Entry Point:** Dashboard or Knowledge Base

```
START: Dashboard
   User sees zone scores:
   • Energy & Power: 🟢 6/7 (Glucose good, but Insulin high)
   ↓
User taps on Energy zone
   ↓
ZONE DETAIL:
   • Blood Glucose: 5.4 🟢
   • Insulin: 3.2 🟡 (slightly high, wants <2.5)
   • HbA1c: 5.4 🟢
   ↓
User taps: [Tips for lowering Insulin]
   ↓
KB ARTICLE: "High Fasting Insulin" (personalized)
   • "Your insulin is 3.2 (target <2.5)"
   • "Possible causes: 1) Too many carbs, 2) Not enough exercise, 3) Stress"
   • "Your context: You're carnivore, fasting 16h, moderate exercise"
   • "Next levers to try:"
     - "Increase strength training (most impactful)"
     - "Extend fasting window to 18h (moderate impact)"
     - "Increase magnesium (small impact)"
   ↓
User reads each lever with mechanism + expected timeline
   ↓
User decides: "I'll add 2 strength sessions per week"
   ↓
User navigates to: [+ Create Experiment]
   ↓
EXPERIMENT FORM:
   • Hypothesis: "Strength training will lower fasting insulin"
   • Duration: 4 weeks
   • Baseline: Insulin 3.2 mU/L (recorded)
   • Target: Insulin <2.5 mU/L
   • Actions: "2 strength sessions per week (M/W)"
   ↓
User clicks: [Start Tracking]
   ↓
SUCCESS: Experiment created, next 4 weeks focused on baseline measurement
   Dashboard now shows: "📊 Active Experiment: Strength Training (Week 1/4)"
   ↓
USER FLOW:
   Week 1: Measures glucose + insulin every 3 days
   Week 2: Adds 2 strength sessions, continues measuring
   Week 3: Notices insulin trending down (3.2 → 3.0 → 2.8)
   Week 4: Final measurement: 2.6 (near target!)
   ↓
EXPERIMENT COMPLETE:
   • Result: Insulin down from 3.2 to 2.6 (+20% improvement)
   • Conclusion: "Strength training effective"
   • Next: Maintain 2x/week, or adjust further
```

**Key Moments:**
- ✓ Personalized suggestions based on user's data + context
- ✓ Mechanism explained (why each lever works)
- ✓ Experiment tracking built-in (before/after, context, duration)
- ✓ Clear progress visualization

**Potential Issues:**
- ❌ KB articles don't mention user's specific situation → feels generic
- ❌ No way to create "experiment" → just measure randomly
- ❌ Can't see impact of specific action → unclear if it worked
- ❌ Experiment forgotten after 4 weeks → no closure or next step

## 🔔 JOURNEY 5: "I Missed a Week. What Did I Miss?"

**Goal:** I traveled and didn't measure for a week. Now I'm home. What's changed?

**Duration:** 3–5 minutes  
**Frequency:** Occasional (after travel, stress, etc.)  
**Entry Point:** Dashboard

```
START: Dashboard
   Last measurement: 2026-02-20 (11 days ago)
   ↓
Notice from app: "It's been 11 days since you measured. Ready to get back on track?"
   [Measure Now] [View Trends] [Catch Up]
   ↓
User clicks: [Measure Now]
   ↓
FORM: New Measurement
   • Date: Auto-filled to today (2026-03-02)
   • Time: 06:00 (expected)
   • Device: Fora 6
   ↓
User enters metrics
   ↓
BEFORE SAVE: "You haven't measured since Feb 20. Changes to expect:"
   • "Glucose may be higher (11-day gap after honey days)"
   • "Ketones may be higher (longer fasting window during travel)"
   • "Consider: timezone changes, travel stress, different food"
   ↓
User saves measurement
   ↓
AFTER SAVE: Gap notification
   "⏸️ 11-day gap detected"
   "Glucose: 5.2 (same as Feb 20)"
   "Ketones: 0.8 (↑ from 0.1, expected from longer fast)"
   "UA: 310 (↓ from 321, good)"
   ↓
ANALYSIS VIEW:
   • "Despite 11-day break, all metrics improved or stable"
   • "Likely due to: no honey during travel, good sleep, low stress"
   • "Trend: Stable (no concern)"
   ↓
SUCCESS: User caught up, understands gap, no anxiety
```

**Key Moments:**
- ✓ App acknowledges gap (doesn't pretend it didn't happen)
- ✓ Explains what to expect (educational, not alarmist)
- ✓ After measurement, contextualizes changes (not just "here's the data")
- ✓ Normalizes breaks (travel happens)

**Potential Issues:**
- ❌ App shows big "warning" about gap → creates anxiety
- ❌ Can't see what changed (glucose vs. 11 days ago) → confusing
- ❌ Measurements before/after gap not labeled → hard to compare
- ❌ No way to mark "I was traveling" → context lost

## 🔐 JOURNEY 6: "Offline Measurement, Then Sync When Home"

**Goal:** I'm at the gym and want to measure, but no WiFi. Sync when I get home.

**Duration:** 1 minute (measure) + 10 seconds (sync)  
**Frequency:** Weekly (gym measurements)  
**Entry Point:** New Measurement button

```
START: User at gym, no internet
   ↓
User taps: [+ Add Measurement]
   ↓
FORM: New Measurement (offline)
   • All fields work normally (no network call yet)
   • Device: [Qardio Arm] (Bluetooth connected)
   ↓
User enters:
   • Weight: 72.8 kg
   • BP: 110/70 mmHg
   ↓
User clicks: [Save]
   ↓
OFFLINE: Measurement saved to local storage
   • Toast: "✓ Saved locally (will sync when online)"
   • App shows badge: "📡 1 pending sync"
   ↓
User returns home, WiFi available
   ↓
APP: Auto-detects internet
   • "Syncing 1 pending measurement..."
   • Spinner spins for 1–2 seconds
   ↓
SUCCESS: 
   • Measurement uploaded to server
   • Badge disappears
   • Dashboard updated
   • Toast: "✓ Synced"
   ↓
DETAILS:
   • If sync fails: "Retry" button visible, data preserved
   • No data loss ever (local + cloud backup)
```

**Key Moments:**
- ✓ No network required to add measurement
- ✓ Auto-sync when available (transparent)
- ✓ Visual indication of pending sync (user knows what's happening)
- ✓ Data never lost (local storage is backup)

**Potential Issues:**
- ❌ Network loss causes error, data lost → devastating
- ❌ Offline measurements disappear → confused user
- ❌ Sync never happens → pending measurements stuck
- ❌ Duplicate syncs if user manually retries → data corruption

## 🎯 DESIGN IMPLICATIONS

From these journeys, we need:

**Screens:**
- ✓ New Measurement form (handles single or bulk entry)
- ✓ Single measurement detail view (with KB link)
- ✓ Trends view (with annotations, easy export)
- ✓ Export/Share interface (PDF, CSV, link)
- ✓ Experiment creation/tracking (optional, Phase 2)
- ✓ Offline indicator + sync status (badge, toast)

**Features:**
- ✓ Context stored with every measurement (journal, tags)
- ✓ KB articles linked from measurements + zones
- ✓ Pattern detection (anomaly highlighting, gap detection)
- ✓ Personalized suggestions (based on user's data)
- ✓ Professional export (PDF with summary + chart)
- ✓ Offline support (local storage + auto-sync)
- ✓ Experiment framework (optional Phase 2)

**Data:**
- ✓ All context preserved (journal, tags, device, location)
- ✓ Timestamps precise (date + time, not just date)
- ✓ Gap detection (identify measurement breaks)
- ✓ Trend calculation (rolling average, anomaly detection)
