## What Went Well

### 1. All planned items completed in a single day
Despite being at the 25-point guideline cap, every item was delivered including the two stretch goals (#158, #159). The phase ordering (path fix first, then spot check, then code changes) kept the flow unblocked.

### 2. @brickos/ui shared package created cleanly
The "prove in app, promote to package" strategy worked. MultiSelect was already battle-tested in the measurements page, so extracting it to `packages/ui` was a straightforward move. The workspace resolution, Docker build changes, and deploy script lockfile handling were more complex but all resolved in-session.

### 3. Spot check found real bugs early
The production v0.23.0 spot check revealed the language-switch-without-refresh bug on zones pages before any user reported it. Quick fix (add `locale` to useEffect deps) prevented a bad UX shipping unnoticed.

### 4. Marker matching dramatically improved
The import pipeline went from failing on basic German column headers ("Blutdruck syst." unmatched, "Blutdruck diast." -> AST) to correctly matching all German BP and standard markers. Three-layer fix: German aliases in marker_matcher, aliases in AI prompt context, source_name priority in enrichment.

### 5. Comprehensive test documentation
Three release documents produced: manual checklist (100 items), testing strategy report, and formal test execution report for security review. This gives an external reviewer everything they need.

## What Could Be Better

### 1. Unplanned work was 43% of total delivery
Almost half the work was unplanned bug fixes discovered during the spot check and import testing. While these were important fixes, they displaced potential Sprint 007 work and made the sprint less predictable.

**Action:** Accept that spot-check sprints will always surface unplanned work. Budget 30% buffer in sprint planning when a spot check is included.

### 2. Six staging deploys in one session
Each deploy takes ~2-4 minutes. Six deploys = ~20 minutes of waiting. Several were for small fixes (i18n key namespace, em-dashes, protocol dropdown labels) that could have been caught locally.

**Action:** Run `pnpm dev` locally and verify i18n/UI changes before deploying. Only deploy when batching 3+ changes or when a backend change needs verification.

### 3. Docker build context change was complex
Moving the frontend Docker build context from `frontend/` to monorepo root (`./`) required changes to Dockerfile, deploy script, .dockerignore, and lockfile handling. The workspace `workspace:*` -> `file:` protocol rewrite in Docker was non-obvious and took multiple iterations.

**Action:** Document the Docker workspace pattern in an ADR. Consider using a simple `cp` in the Dockerfile instead of the sed-based rewrite if adding more packages.

### 4. Deploy script version mismatch warnings are confusing
The deploy script warns about version mismatch when the VERSION in deploy.sh doesn't match the API's reported version. But with auto-incrementing build numbers, this is always a mismatch on frontend-only deploys. The warning is noise.

**Action:** The version assertion should compare base versions (0.23.0 = 0.23.0) and only warn if they truly differ, not if a build suffix differs. Partially fixed but could be cleaner.

### 5. No automated test for new conversation delete endpoint
The DELETE /doctor-chat/conversations/:id endpoint was added but has no DB test. This was a conscious trade-off (ship fast, test later) but should be addressed in Sprint 007.

**Action:** Add `test_delete_conversation` to `doctor_chat_test.rs` in Sprint 007.

## Surprises

1. **ODS multi-sheet bug was subtle** - LibreOffice with `-1` (all sheets) produces separate CSVs per sheet. The code picked the first one alphabetically ("Ampel_Logik") instead of the data sheet ("Messprotokoll"). Took investigation to find the root cause.

2. **"ast" matching inside "diast"** - The 3-character minimum for substring alias matching was too low. Raising to 4 prevented the false positive but required checking that no important 3-char aliases broke (they didn't - they match in step 1, exact match).

3. **pnpm workspace resolution in Docker** - pnpm's strict store doesn't allow accessing packages not declared in package.json, even if physically present in node_modules. The `node-linker=hoisted` flag solved this for Docker builds.

4. **Newsletter subscribers table was disconnected** - Signup stored consent in `user_profile` but never created a row in `newsletter_subscribers`. Two separate systems for the same concept, likely from different implementation phases.

## Key Decisions Made

| Decision | Rationale |
|----------|-----------|
| Separate URLs for Dr. Alex landing vs conversation | Same-URL state management was fragile; URL routing is the web-native solution |
| First-sheet-only for ODS import | Data is always on the first sheet; explanation sheets caused false rejections |
| Source column name priority over AI in marker enrichment | AI can misidentify foreign-language headers; our alias map is more reliable |
| @brickos/ui as workspace package (not npm publish) | Too early for external publish; workspace link is simpler and sufficient |
| Soft delete for conversations | Consistent with measurements; audit trail preserved |
| Auto-increment build numbers only for staging | Production uses clean semver; staging needs visible version changes for verification |
