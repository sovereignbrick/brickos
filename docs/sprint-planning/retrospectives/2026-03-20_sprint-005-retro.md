## What Went Well

1. **All phases delivered including stretch.** First sprint where the stretch goal (Phase 5) was completed. Total ~45 pts delivered.

2. **Smart Import (Phase 6) was well-designed.** Design 015 was comprehensive enough that implementation was straightforward. The review screen, backend extraction, and frontend integration all came together cleanly.

3. **Production hardening caught a real issue.** The ntfy token was non-functional — notifications would have silently failed on any production incident. Found and fixed during P4-1.

4. **Backup restore test was valuable.** First time actually testing a restore. Only issues were expected missing roles (`sh_readonly`, `sh_app`), data was fully intact.

5. **Content migration at scale worked.** 325 UPDATE statements for 92 markers x 2 locales x 2 fields, all idempotent. Medical content was accurate and concise.

6. **Admin error handling was a quick win.** 4 files, 37 insertions — small change but prevents the "why is this tab empty?" confusion that hit in Sprint 004.

---

## What Could Be Better

1. **ntfy token was broken since Sprint 004.** The monitoring stack was deployed with a placeholder token that was never replaced with a real one. No alert ever fired because production has been stable — but if it had gone down, we wouldn't have been notified.

2. **Smart Import prompts need real-world testing.** The Claude extraction prompts handle the sample images well in analysis but haven't been tested end-to-end on staging yet. Edge cases (multi-sheet files, mixed languages, unusual date formats) are untested.

3. **No RC testing for this sprint yet.** All code is committed but not deployed or manually tested on staging. Previous sprints have shown that deploy + RC testing often reveals issues.

4. **Conversation crash lost context.** The session crashed mid-work on Smart Import, requiring reconstruction of what had been done. All code was preserved in the working tree but the prompt context was lost.

5. **Phase 3 was lighter than planned.** The sprint plan called for "systematically test every admin tab" (P3-1, 3 pts) but we only verified endpoints return proper status codes and fixed error handling. A full E2E walkthrough of each tab with real data wasn't done.

## Key Decisions

1. **Summary table rejection in Smart Import** — Rather than trying to import averaged data, we reject it with a clear error message and ask the user to export raw data instead.

2. **Calculated markers skipped during import** — BMI, GKI, WHtR are computed by our system, so importing them from external sources would create conflicts. Marked as `calculated_skip` in the review screen.

3. **Year inference in prompts** — Device apps often show DD/MM without year. Added explicit prompt rules for chronological order year-boundary detection rather than trying to solve it in code.

4. **Toast vs error state for admin panels** — Used error state (red banner) for tabs where errors were completely silent (audit logs, AI usage). Used toast.error for tabs that just needed catch block fixes (affiliates, promotions).
