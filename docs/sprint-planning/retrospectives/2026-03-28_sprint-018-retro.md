## What Went Well

1. **All 16 pts delivered in one sprint** -- the design-first approach from Sprint 018 planning paid off. Dependency graph was accurate, and the sequential P0-first execution order prevented rework.

2. **Per-date calculated markers shipped clean** -- the `enrich_with_values_at_date()` function was the right abstraction. Historical GKI/Dr. Boz/HOMA-IR computation now works across multi-date imports without touching the single-measurement handler.

3. **German lab alias expansion caught edge cases** -- adding Sexualhormonbindendes, Follikelstim., and other German lab-specific aliases improves import quality for the primary user base. The 4-char minimum substring rule prevented false positives.

4. **Hotfix turnaround was fast** -- route order bug (history route after `/{id}`) and JSON array parsing were caught during staging verification and fixed in one commit before production deploy.

---

## What Didn't Go Well

1. **Import rollback button does not work** -- the `/measurements/imports` page renders with a rollback button, but clicking it does not trigger the `POST /import/sessions/:id/rollback` endpoint. Likely a frontend event handler or API wiring issue. Filed as #299.

2. **Desktop crash during production promotion** -- lost context mid-deploy when the desktop crashed. Had to recover state and resume the deploy manually. Second sprint in a row with a crash during critical operations.

3. **ntfy still broken** -- carried from Sprint 017. Deploy notifications remain silent. This is now the third sprint where ntfy is non-functional.

---

## Key Lessons

1. **Route ordering matters in Actix-web** -- parameterized routes (`/{id}`) must come after literal routes (`/history`). This is a repeat pattern; consider a lint or comment convention to prevent future misorderings.

2. **Claude JSON extraction returns arrays, not objects** -- when Claude returns structured data from PDF extraction, it may return a JSON array of key-value pairs rather than a flat object. `extract_field_str` needed to handle both formats.

3. **Test rollback flows before shipping** -- the rollback button was visually present but non-functional. End-to-end testing of destructive actions (rollback, delete) should be an explicit checklist item.

4. **Desktop stability is a recurring risk** -- two sprints in a row lost progress to desktop crashes. Consider more frequent auto-saves or switching to a more stable environment for critical deploys.
