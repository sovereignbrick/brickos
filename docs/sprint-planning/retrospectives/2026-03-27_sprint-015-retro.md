## What Went Well

1. **Reduced sprint scope worked** -- 32 pts vs 54 in Sprint 014. Finished in 1 day with no rushed work. The 30% buffer recommendation from Sprint 014 retro proved correct.

2. **Dependency bumps were clean** -- sentry, jsonwebtoken, rand all updated without breaking changes (only rand 0.10 needed a 1-line import fix). 138 tests still pass.

3. **Security posture significantly improved** -- GitHub secret scanning + push protection enabled, Semgrep SAST in CI, Trivy container scanning, cargo deny, npm audit. Network scan identified 2 real findings (port 8080 exposure, SSH hardening).

4. **OpenVAS on local machine was the right call** -- production VPS only has 1 vCPU and 3.8 GB RAM, too small for OpenVAS. Local install on 6TB drive with bind mounts keeps system disk clean.

---

## What Didn't Go Well

1. **Greenbone container registry unreliable** -- the official multi-container setup failed repeatedly with TLS timeouts from registry.community.greenbone.net. Switched to immauss/openvas all-in-one from Docker Hub which pulled instantly. Lesson: always have a fallback image source.

2. **OpenVAS feed sync takes 30+ min** -- first-run feed initialization blocked the vulnerability scan. Should have started the pull earlier in the sprint. Feeds still syncing at sprint end.

3. **deploy.sh version assertion needs updating** -- the bump_staging_version fix from Sprint 014 means deploy.sh now reports a "version mismatch" on staging (expects -b1 suffix, API reports clean version). Not a real issue but the assertion should be updated.
