## What Went Well

1. **Dependabot 38 -> 0 in one sprint** -- the key insight was that most "vulnerabilities" came from stale lockfiles (orphan package-lock.json files that Dependabot was scanning). Removing them + upgrading jsonwebtoken cleared the board entirely. Efficient approach.

2. **Design-first for security testing (Design 034)** -- wrote the architecture doc before diving into implementation. Identified blind spots (no DAST, no fuzzing, no load testing of auth flows) and created a prioritized backlog (#290-#294). Zero rework.

3. **RC test caught a real blocker** -- jsonwebtoken v10 CryptoProvider panic would have taken down production on first login. The compile succeeded but the runtime crash only manifests when JWT encoding/decoding is called. RC testing before production deploy saved us.

4. **Revenue Simulator shipped cleanly** -- admin-only feature, no user-facing risk, good for business planning conversations.

---

## What Didn't Go Well

1. **jsonwebtoken v10 migration was incomplete** -- the v9->v10 upgrade compiled fine but panicked at runtime because `CryptoProvider::install_default()` wasn't called. The `rust_crypto` Cargo feature is necessary but not sufficient when both crypto backends exist in the dependency tree. This was only caught during RC testing, not during local development (local tests don't exercise the main.rs startup path with full JWT flow).

2. **ntfy token broken on VPS** -- pre-flight check reported HTTP 000 from VPS. The token in `.env.staging` may have expired or been rotated without updating both `.env.staging` and `.env.monitoring`. Deploy notifications are now silent.

3. **OpenVAS deferred for second sprint** -- SCAP feeds are still syncing after the data wipe in Sprint 016. This is now blocking a proper vulnerability scan for two sprints running.

4. **Desktop crash during RC test** -- lost test progress when the desktop crashed mid-RC. No state was saved. Had to restart the entire checklist from scratch.

---

## Key Lessons

1. **Runtime-only failures from dependency upgrades are real** -- `cargo check` and `cargo test` passed for jsonwebtoken v10, but the actual CryptoProvider initialization only runs in main.rs. Add integration tests that exercise JWT encode/decode in the test harness, or add a startup self-test.

2. **Save RC test state incrementally** -- the desktop crash cost 20 minutes of re-testing. Checklist should be saved to disk after each layer, not held in memory.

3. **Stale lockfiles create phantom Dependabot alerts** -- orphan package-lock.json files (from old workspace configurations or copy-paste) get scanned by Dependabot even if npm is not used. Always grep for `package-lock.json` after workspace restructuring.

4. **ntfy tokens need a rotation checklist** -- when rotating, update: `.env.staging`, `.env.monitoring`, and test from both local and VPS. The pre-flight check exists but the fix workflow isn't documented.

5. **OpenVAS feed sync takes days, not hours** -- plan around it. Don't schedule OpenVAS scan in a 1-day sprint unless feeds are confirmed ready beforehand.
