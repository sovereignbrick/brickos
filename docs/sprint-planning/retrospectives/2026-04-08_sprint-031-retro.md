## What Went Well

1. **Root cause found fast** -- The session persistence issue (#0370/#0371) was caused by Sovereign Link's `extract_user_id()` not parsing JWT from Authorization header. One fix resolved both issues.

2. **E2E tests caught real bugs** -- Playwright tests on demo.brickos.io revealed the exact failure point (analytics page -> /api/v1/links -> 401). Without E2E we'd still be guessing.

3. **Massive tab elevation** -- All 11 SHI admin tabs elevated to /platform/* in one batch. Same components, no duplication, all working.

4. **Gatus restructured** -- 5 logical groups (per app + staging + infra), production first. Much cleaner.

5. **Zero vulnerabilities** -- pnpm audit clean after hono overrides.

## What Didn't Go Well

1. **Login logo still broken** -- 3 attempts (getBrandConfig, useBrand hook, plain img, middleware cookie) and still shows SHI logo. Need to investigate why the brand_context cookie isn't being read on first render.

2. **QR code iterations continue** -- 5th attempt with Pillow-generated white-bg PNG. Should have done this from the start instead of trying SVG approximations.

3. **Rate limiter wasn't in docker compose** -- Added to .env.staging but env vars only pass via compose environment block. Wasted time debugging.

## Lessons Learned

1. **Check request extensions vs headers** -- When integrating two Rust services (SHI middleware + Sovereign Link handlers), verify how auth data is passed. Extensions aren't shared across crate boundaries.

2. **Next.js Image caches SSR src** -- Dynamic image sources that change client-side don't work with Next.js Image component. Use plain `<img>` or middleware-based approach.

3. **Docker compose env vars != .env file vars** -- env_file is for variable substitution in YAML, not for passing to containers. Need `environment:` block.
