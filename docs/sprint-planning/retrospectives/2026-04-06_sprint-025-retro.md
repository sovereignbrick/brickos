# Sprint 025 Retrospective

**Sprint:** 025 - Code Quality, Testing & Security Hardening
**Duration:** 2026-04-06 (1 day)
**Points planned:** 35
**Points delivered:** 35
**Version:** v0.35.0 -> v0.36.0

## What Went Well

- **Parallel execution** across 3-4 agents made the 35-point sprint achievable in one day. Phase 1 (3 tracks), Phase 2 (3 tracks), Phase 3 (2 tracks), Phase 4 (1 track) all ran concurrently.
- **Business logic audit** (#314) documented 138 acceptance test scenarios across 16 areas - this is now the definitive reference for what the platform does.
- **Security hardening** delivered real value: AI prompt injection sanitization, incident response procedure, detect-secrets pre-commit, JWT rotation mechanism.
- **Cloudflare Tunnel** for ntfy fully resolved the VPS IP exposure issue. DNS now returns Cloudflare IPs, not the origin server.
- **K6 load testing** confirmed healthy baseline: p95 latency 36ms, 0% error rate across 6 public endpoints.
- **VPS fully updated** - kernel 6.8.0-107, all packages current including cloud-init 25.3.

## What Didn't Go Well

- **Cloudflare Tunnel setup** required interactive browser auth - couldn't automate via SSH. Had to guide user through manual steps. Also hit Cloudflare Access policy blocking tunnel traffic (302 redirect) - had to identify and remove the Access application.
- **cargo-fuzz** couldn't be fully tested - requires nightly Rust which wasn't available in the dev environment. Fuzz targets are set up but unverified.
- **pgAudit log ingestion** not complete - table and endpoint created, but no mechanism to populate the table from PostgreSQL logs yet. The endpoint works but returns empty results.

## Lessons Learned

1. **Cloudflare Access and Tunnels interact** - if you have an Access policy on a domain, tunneling to it still requires Access authentication. Must remove or bypass the Access application for services with their own auth (like ntfy).
2. **Major apt package upgrades** get "kept back" by `apt upgrade` - need `apt install <package> --allow-change-held-packages` to force the update.
3. **138 business rules** is a lot - the audit revealed the platform is more complex than it appears. Good to have documented before adding more features.
4. **AI sanitization is simple but effective** - 10 pattern matches catches most prompt injection attempts. Not foolproof, but raises the bar significantly.
