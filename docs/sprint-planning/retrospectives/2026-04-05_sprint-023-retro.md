## What Went Well

- **Design-first approach** paid off again. Search design doc (035) + E2E design doc (036) caught scope issues before code. The Dr. Alex document analysis design doc (037) saved an estimated 21 pts of future rework by defining data model, prompts, and tier gating upfront.
- **Pre-existing bugs found** during search testing: calculated marker "Recent Measurements" was empty for all 8 calculated markers (GKI, BMI, etc.). Fixed a production bug as a side effect of the sprint.
- **Unified AI credit pool (#301)** was already implemented from Sprint 019 -- saved 5 pts of work.
- **Search feature complete in one day** -- backend (migration + 3 endpoints + 1456 indexed rows) + frontend (overlay, results page, navbar) delivered and tested.
- **ntfy root cause found** -- the .env.staging file had unquoted angle brackets in MAILGUN_FROM, causing silent `source` failures. Simple fix, big impact.

## What Didn't Go Well

- **8 staging deploys** for iterative search fixes. Each deploy took ~14 min (full --no-cache Rust build). ~2 hours lost to builds.
  - **Root cause:** Staging deploy used `--no-cache` like production.
  - **Fix applied:** Staging now uses Docker layer caching. Production keeps `--no-cache`.
- **Frontend/backend contract mismatch** crashed the search page on first staging deploy.
  - Backend returned `{ data: { total_results, facets: [{type,count}] } }`
  - Frontend expected `{ total, facets: Record<string,number> }`
  - Contract tests used hardcoded samples matching the SPEC, not the IMPLEMENTATION.
  - **Fix:** Contract tests rewritten with actual API response shapes. E2E test added that validates real API response structure.
- **PostgreSQL regconfig cast** bit us twice -- migration AND handler both needed `::regconfig` on CASE WHEN expressions for `to_tsvector`/`plainto_tsquery`. Should have caught this in local testing.
- **Bilingual search** required 3 iterations to get right (locale filter, DISTINCT ON ordering, subquery approach). The design doc spec was clear but the PostgreSQL implementation was trickier than expected.
- **Web content deep links** pointed to wrong URLs initially (raw DB page slugs instead of actual website paths from sitemap).

## Lessons Learned

1. **Always validate API responses against frontend types with real calls** -- not hardcoded samples. Added to memory as `feedback_spec_vs_implementation_testing.md`.
2. **PostgreSQL `to_tsvector(CASE WHEN ... END, text)` needs `::regconfig` cast** -- the text search config name from a CASE expression is type `text`, not `regconfig`. PostgreSQL doesn't auto-cast.
3. **`DISTINCT ON` kills score ordering** -- PostgreSQL requires ORDER BY to start with DISTINCT columns. Use a subquery to deduplicate first, then sort by score in the outer query.
4. **Staging deploy caching is essential** for iterative development. The --no-cache safeguard is for production only.
5. **Local issue tracker first, then GitHub** -- added to memory as `feedback_local_issue_tracker.md`.
6. **Demo data separation needed** -- can't test destructive features on staging when it shares data with the website demo profiles. Created #306.
7. **Deploy optimization** -- created #307 for further improvements (build on VPS, component-only deploys).
