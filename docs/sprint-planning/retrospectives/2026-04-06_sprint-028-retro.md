## What went well

1. **Audit-first approach saved significant time.** Before writing any code, we audited all 18 M1 issues against the existing Sprint 027 codebase. 12 were already done. This prevented rebuilding what existed and focused effort on the 6 real gaps.

2. **Design-first, then implement.** Three design specifications (003 multi-tenant, 004 schema elevation, 005 sprint plan) were written before any code. The table classification (39 platform, 53 SHI, 10 ambiguous) gave precise scope. No scope creep during implementation.

3. **Integration tests caught a real bug.** Issue #316: the standalone REST API had no auth middleware wired. The API endpoints returned 401 for all programmatic access. This would have shipped broken without the test suite.

4. **Zero-downtime migrations worked.** `ALTER TABLE SET SCHEMA` is metadata-only. All 5 platform migrations ran on staging and production with SHI live. No downtime, no data loss, no errors.

5. **Feature flags provide clean separation.** `--features standalone` and `--features platform` compile independently with zero cross-contamination. 35 tests pass in standalone, platform compiles clean.

6. **Platform smoke test proved its value immediately.** The first run on production caught the search_path issue (backend needed restart after `ALTER DATABASE SET search_path`). Without the smoke test, we might not have caught this until a user reported broken redirects.

7. **Per-environment test credentials worked.** Staging (demo@sovereignhealth.io) and production (optimized@sovereignhealth.io) demo users enabled automated verification on both environments.

## What didn't go well

1. **Deployment workflow was not followed initially.** We created the PR before writing sprint artifacts (retrospective, release notes, version bump). This violated our own SPRINT_PLANNING.md process. The user caught this during review.

2. **Deployment workflow didn't exist at platform level.** The existing deployment doc was SHI-specific. We had to create `docs/deployment/README.md` during sprint closing, adding unplanned work.

3. **Testing architecture was SHI-specific.** No platform smoke test, no DB migration test, no cross-app tests existed. We had to design and implement `docs/design/013-testing-architecture.md` and 3 test scripts during the sprint, which wasn't planned.

4. **NIP-89 relay publishing incomplete.** The signing works (Schnorr BIP-340), but actual WebSocket relay publishing requires the `tungstenite` crate which we didn't add. Falls back to logging. This is a known limitation, not a regression.

5. **`ALTER DATABASE CURRENT` syntax doesn't work.** Both staging and production required manual `ALTER DATABASE <name> SET search_path` instead. The migration SQL used `CURRENT` which PostgreSQL doesn't support in that context. Had to fix manually on both environments.

6. **Encrypted user_profile data can't be migrated at SQL level.** Migration 005 tried to copy user_profile data to the split tables, but the columns contain AES-256-GCM ciphertext. Only the application layer (with the user's encryption key) can decrypt and re-encrypt. The billing_profile (non-encrypted) copied fine.

7. **Legacy users without personal orgs.** The DB integrity test flagged 16 users on staging without personal organizations. These were created before the org migration. Not a regression from our work, but a pre-existing data consistency gap that needs a backfill migration.

8. **Gatus config YAML syntax error.** First attempt to add BrickOS monitoring endpoints appended them inside the `alerting:` block instead of `endpoints:`. Gatus crash-looped until fixed.

9. **GitHub GraphQL API rate limit (0/0).** The PAT doesn't have GraphQL access. Had to fall back to REST API for all 29 issue creations. Wasted time debugging.

10. **No smoke tests were run before we asked about production promotion.** The user had to remind us about following the deployment workflow and running smoke/RC tests.

## What to change

### Process

- **Pre-PR checklist is mandatory.** Before creating any PR, verify: sprint summary updated, retrospective written, release notes created, version bumped. Add this as a comment template in the PR body.
- **Elevate infrastructure docs BEFORE adding new apps.** Deployment workflow, testing architecture, and monitoring should be platform-level from the start. We retrofitted all three during this sprint.
- **Run smoke tests automatically after every deploy.** Add `bash tests/platform-smoke.sh $ENV` as the last step in `ops/deploy.sh`. Don't rely on manual execution.
- **Follow the deployment workflow strictly.** The workflow exists for a reason. Skipping steps (smoke tests, RC testing) creates risk. The user should not have to remind us.

### Technical

- **Fix `ALTER DATABASE CURRENT` in migration 001.** Replace with parameterized database name or document that it requires manual execution.
- **Add tungstenite crate** for NIP-89 and future NOSTR WebSocket communication.
- **Create backfill migration** for legacy users without personal organizations.
- **User_profile split needs application-level migration.** The SQL-level copy doesn't work for encrypted columns. Need an API endpoint or migration script that decrypts, splits, and re-encrypts.
- **GitHub PAT needs GraphQL scope.** Or switch entirely to REST API for issue management.

### Testing

- **Platform smoke test should be a post-deploy hook**, not a manual step.
- **Add Sovereign Voice to smoke test** with systemd + schedule verification (done in this sprint).
- **Write Sovereign Voice unit tests** (currently 0). At minimum: publisher, scheduler, config.
- **DB migration testing** should run against a disposable database in CI, not only manually on staging.

## Decisions made

| Decision | Rationale |
|----------|-----------|
| Schema name: `brickos` | Brand-consistent, clear ownership |
| Full encryption at platform level | Forces all apps to adhere to high security standard |
| Auth extraction: shared crate (`packages/brickos-auth/`) | Each app embeds auth handlers, no microservice needed yet |
| Separate backup: platform DB vs app DBs | Platform schema backed up more frequently |
| Per-app versioning and tagging | Apps release independently: `sovereign-link/v0.2.0`, `brickos-platform/v0.1.0` |
| Deployment workflow elevated to platform level | One workflow for all apps, per-app deployment units |
| Production demo user for automated tests | `optimized@sovereignhealth.io` for production smoke tests |
| Staging nginx basic auth in test scripts | Automated tests can authenticate through nginx |
