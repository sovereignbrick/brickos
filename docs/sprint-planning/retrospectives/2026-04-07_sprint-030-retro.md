# Sprint 030 Retrospective

**Sprint:** 030 - Sovereign Link Hardening + Platform GUI Foundation
**Date:** 2026-04-07
**Duration:** 10 days
**Points:** 41 delivered (target 44)

---

## What Went Well

1. **Two parallel tracks worked** -- Sovereign Link hardening (Days 1-6) and Platform GUI (Days 5-9) ran independently without blocking each other.

2. **Platform GUI foundation shipped** -- 28 routes, role-based sidebar, dashboard with real data, service health monitor, click analytics with Recharts, users tab elevated. All live on app.brickos.io.

3. **Domain infrastructure** -- Four new brickos.io subdomains (app, demo, api, status) configured, SSL working via Cloudflare wildcard cert, nginx routing with unified app paths.

4. **Website animation fixed** -- Replaced iframe with inline SVG React component. Works on Brave, Chrome, Firefox.

5. **Voice URL shortening** -- End-to-end integration: service account created, config added, scheduler rebuilt. Next NOSTR publish will auto-shorten URLs.

6. **Design docs** -- Two comprehensive design documents (014 Platform GUI, 015 Unified Routing) with ASCII wireframes, role matrices, and phased implementation plans.

7. **46 tracker issues created** (#0330-#0378) -- thorough documentation of backlog.

## What Didn't Go Well

1. **Session persistence on brickos.io** -- The same Next.js app serving both SHI and platform admin on different domains causes cookie/session confusion. Login works for /platform but drops for SHI pages. This should have been anticipated when planning the domain routing.

2. **QR code iterations** -- 4 attempts to get the QR code right (orange SVG -> dark SVG -> dark PNG -> needs light PNG). Should have looked at the actual brand assets first before coding.

3. **Nginx routing complexity** -- Multiple redeploys to fix trailing slash issues, catch-all proxy blocks, and Next.js 308 redirects. nginx + Next.js + Cloudflare is a tricky combination.

4. **Login rate limiter** -- Blocked manual testing and E2E tests. In-memory rate limiter requires backend restart to clear. Should have a test-mode bypass.

5. **Frontend lockfile sync** -- Kept failing pre-flight checks. The separate frontend lockfile for Docker is a maintenance burden.

6. **No E2E tests for new features** -- Playwright was available but not used until Day 10. Should have been integrated from Day 1.

## Lessons Learned

1. **Test on the target domain early** -- Don't wait until Day 10 to test brickos.io routing. Should have verified domain routing on Day 5 when the layout was built.

2. **Check brand assets before coding** -- Look at the actual PNG/SVG files instead of guessing colors from memory.

3. **Rate limiter needs test mode** -- Every staging/dev environment needs a way to bypass rate limiting for automated testing.

4. **E2E first, not last** -- Playwright E2E tests should be written alongside features, not as an afterthought on the last day.

5. **Cookie domain strategy before multi-domain** -- When serving the same app on multiple domains, plan the cookie/auth strategy upfront.
