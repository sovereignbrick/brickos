# Sprint 019 + 020 Retrospective

**Date:** 2026-04-04

## What went well

1. **Design-first approach paid off again** — the design doc (017-import-pipeline-evolution.md) guided all Sprint 020 work cleanly
2. **Combined testing saved time** — testing both sprints together caught integration issues early
3. **User testing found real issues** — HbA1c unit confusion, marker dedup, rollback UX, demo data leaking into measurements list
4. **Fuzzy matching works** — Levenshtein distance catches OCR typos without false positives
5. **Category-based prompts are cleaner** — each prompt is focused and shorter than the monolithic one
6. **Unified import review header** — consistent UX across all import types, user defaults pre-filled

## What didn't go well

1. **Migration checksum mismatch (AGAIN)** — modifying migration 20260326000001 broke staging deploy. We've now added a pre-flight check to prevent this.
2. **Intermittent Anthropic API timeouts** — network instability from Docker containers caused repeated "upstream error". Required retry logic on ALL API calls.
3. **Browser caching of API responses** — measurements page showed stale data after rollback. Required no-cache headers.
4. **Demo data leaking into measurements list** — `is_demo = false` filter was missing from list query. Root cause of "rollback not working" reports.
5. **AI field name inconsistency** — Claude returns `marker_name`, `name`, or `marker` depending on the prompt/run. Required triple fallback.
6. **HbA1c unit confusion** — AI mislabels mmol/mol as %. Required unit conversion + validation.
7. **Multiple deploys to staging** — 5 deploy cycles to fix issues found during staging testing.
