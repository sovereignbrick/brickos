## What Went Well

1. **Sprint 004 core was fast.** Phase 1-3 + 5 were done in the first part of the session. The planned work was well-scoped.

2. **RC testing caught real bugs.** The testing checklist found: audit logs broken (cookie vs localStorage), influence factor import 500 (missing brand column), marker translations mostly empty, tier DE translations missing, numeric inputs accepting text, tooltip styling inconsistent.

3. **Notification system shipped clean.** 17 hooks across auth, billing, security — all fire-and-forget, build + clippy clean on first try.

4. **Documentation debt cleared.** 16 ADRs, deployment docs, and the RC checklist template will pay dividends in future sprints and onboarding.

5. **Deploy script is reliable.** 8+ staging deploys in one session, all successful. The preflight checks, DB backup, and version assertion work well.

---

## What Didn't Go Well

1. **RC testing found too many issues post-deploy.** The bulk commit (bb0da84) had a TypeScript error (`scoreMarker` used before declaration) that only surfaced during the Docker build. Local `pnpm build` should be run before committing large frontend changes.

2. **Frontend/backend contract mismatches.** The audit logs tab was completely broken — wrong endpoint (`event-logs` vs `events`), wrong response format (`data[]` vs `data.entries[]`), wrong field names (`timestamp` vs `created_at`), wrong auth method (`localStorage` vs cookies). These should have been caught by integration testing or at least manual testing before the component was committed.

3. **Content tables were a mess.** Two parallel systems (marker_content vs marker_translations) were never synced. The admin panel showed empty fields because it reads marker_translations, while the rich content lived in marker_content. This required 3 migrations to fix.

4. **Native date picker light theme remains unfixed.** Tried CSS color-scheme, Tailwind arbitrary properties, inline styles with MutationObserver — none worked on Chrome Linux. The proper fix is to replace the native input with react-datepicker.

5. **Multiple redeploys during RC testing.** 8 staging deploys in one session means we were fixing things reactively rather than proactively. Each deploy cycle is ~2 minutes — that's 16 minutes of deploy waiting.

## Key Learnings

- **Admin panel is a separate integration surface.** It has its own fetch functions, its own auth handling, and its own response parsing. It needs dedicated testing — not just "the API works."
- **Translation content needs a single source of truth.** Having marker_content AND marker_translations was confusing. The sync migration fixed it, but going forward, marker_translations should be THE table that the admin edits, and marker_content should be deprecated or merged.
- **The RC checklist pays for itself.** Every item we tested either passed or revealed a real bug. The checklist should be run systematically, not ad-hoc.
