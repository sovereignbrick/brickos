# Sprint 027 Retrospective

**Sprint:** 027 - Sovereign Link v1.0
**Duration:** 2026-04-06 (1 day, planned 7)
**Points planned:** 39
**Points delivered:** 39
**Version:** Sovereign Link v0.1.0 (standalone mode)

## What Went Well

- **Parallel agent execution** delivered 7 days of planned work in ~6 hours. Each phase (A/B/C) was a single agent prompt that built all tasks for that phase.
- **Feature flag architecture** worked cleanly from day one. `--features standalone` and `--features platform` never conflicted after fixing the default feature issue.
- **Existing code reuse**: LinkStore trait was already defined, redirect/QR handlers already worked. The new code layered on top without breaking platform mode.
- **NOSTR NIP-98 implementation** was cleaner than expected. secp256k1 crate handles BIP-340 schnorr verification directly. NIP-07 browser extension integration is just a few lines of JS.
- **14MB binary** -- well under the 20MB target. Zero runtime dependencies.
- **Port to SHI** was smooth: same verification function, just adapted to SHI's Postgres/JWT patterns. The AuthProvider trait design from the spec proved its value.

## What Didn't Go Well

- **Feature flag gotcha**: `default = ["platform"]` meant `--features standalone` enabled BOTH features. Had to use `--no-default-features --features standalone`. Should have caught this in the design.
- **No actual Docker build tested** -- created Dockerfile but didn't build/run the image (too slow in sprint context). Should test before shipping.
- **NIP-89 publisher is log-only** -- actual relay publishing needs a service keypair. Documented for v1.1 but users expected it to "just work".
- **Start9 package untested** -- manifest created but no Start9 dev environment to test .s9pk build.

## Lessons Learned

1. **Feature flags need `--no-default-features`** when testing non-default features. The `default = ["platform"]` + `--features standalone` activates BOTH.
2. **Trait-first architecture pays off** -- defining LinkStore/UserStore/AuthProvider traits before implementation made the SQLite backend drop in cleanly.
3. **askama templates work great for sovereign apps** -- server-rendered HTML with no JS deps, dark theme via CSS variables, works with JS disabled.
4. **NIP-98 is the ideal sovereign auth** -- no email required, no third-party OAuth, user controls their own keys. The secp256k1 verification is lightweight.
5. **Port-back pattern works** -- building NOSTR auth on the simple app first, then porting to SHI, caught zero issues. The trait design made it plug-and-play.
